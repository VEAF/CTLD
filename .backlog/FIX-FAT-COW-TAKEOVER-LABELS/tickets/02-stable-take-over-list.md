# 02 — The "Take over a Fat Cow" list holds still

**Status:** ✅ done (PR #NN) · **Type:** AFK

## Parent

[PRD — FIX-FAT-COW-TAKEOVER-LABELS](../PRD.md), [ADR 0027](../../../dev/adr/0027-stable-f10-entries.md). Stories 1 to 5, 8 and 13 to 20. GitHub issue #298.

## What to build

The list a pilot reads stops changing under their finger, and a click always reaches the cow the entry names.

- **Labels.** One entry per cow that can be taken over, named "Fat Cow #N — waiting" (released), "Fat Cow #N — going home to <base>" or "Fat Cow #N — going home" (no base known), with the cow's number from ticket 01. No distance, nothing that moves between two events.
- **Order.** By cow number, ascending, whatever the distances. "Nearest first" is dropped.
- **No periodic refresh.** The timer that rebuilds the menus every 30 s, its period, the function it calls and the parameter that limited a rebuild to the candidate pilots (used only by that function) are removed. The menus are still rebuilt by every event that changes the cows that can be taken over (a cow destroyed or vanished, its arrival at home, its return home, its release, a take-over); nothing else is needed, and a click on an entry whose cow is gone still answers "This Fat Cow is no longer available."
- **The texts.** The three labels are changed texts, each a single literal passed to the translation function; dictionaries regenerated by the build, French and Spanish provided, Korean flagged for review.
- **The tests.** A regression test against the `missionCommands` double that recycles ids as DCS does (the one of the stable-entries spec), red first: two successive refreshes with a cow that came closer, and no entry created or removed. The existing assertions on the old labels with a distance, and the test that the distances are updated every so often, assert the behaviour being removed: they are rewritten.
- **The documentation.** The pilot guide (English and French) describes the list as it now is: one stable entry per cow, in the order of their numbers, named with its number and state; the distance comes in the message the flight receives and in the confirmation of the take-over. The mission maker's page that mentions the take-over is adjusted only if it claims the distance.
- **The CHANGELOG** records it under *Fixed*. No configuration key: no `configVersion` change, no catalogue shape.

## Acceptance criteria

- [x] Two successive refreshes of the list, with a cow that came closer in between, create and remove no entry.
- [x] Two cows in the same state get two distinct labels; the label carries the number and the state, for each of the three states, and no distance.
- [x] The order is the same whatever the distances, including when they invert.
- [x] After two cows swap their distance ranks, the first entry still takes the cow it names.
- [x] The periodic refresh is gone (no timer registered, no function, no unused parameter), and every event that changes the cows that can be taken over still rebuilds the menus.
- [x] The take-over itself, its messages and its refusal for a cow no longer available behave as before.
- [x] The new regression test fails before the change, for the right reason (the entry is recreated), and passes after it; the rewritten assertions describe the new labels.
- [x] The dictionaries are regenerated and the new labels have French and Spanish translations; the Korean ones are flagged for review.
- [x] The pilot guide (English and French) and, if needed, the mission maker's page, and the `CHANGELOG`, are updated.
- [x] `busted tests/ci/` green; luacheck clean.

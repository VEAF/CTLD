# 01 — A failed equipment request tells the pilot and the log

**Status:** ✅ done (PR #NN) · **Type:** AFK

## Parent

[PRD — FIX-REQUEST-EQUIPMENT-SILENT-FAILURE](../PRD.md). Stories 1-9.

## What to build

In the *Request Equipment* callback, report a request that produces nothing: an `ERROR` log line (item, unit, zone, reason)
and a failure message to the pilot's group ("Request failed: the equipment could not be brought out."), for a single crate
with no descriptor, a single crate whose creation returns nothing (spawn-plan path and radial path), a set that creates no
crate, and a vehicle whose creation returns nothing — which must no longer announce "Vehicle ready for loading". A partial
set keeps its count message and logs a `WARNING`. The build adds the new i18n key; translate FR, ES and KO.

Tests first, in a new functional spec built on the existing Request Equipment spec's harness: each failure case gives the
message and the `ERROR`; the message is French in French; the successful single crate, set and vehicle give no failure
message; a partial set warns. Watch them fail, then implement.

Finish the lot: CHANGELOG, backlog index and statuses, PR.

# FIX-CONFIG-NEW-LISTS — a list newer than the mission configuration is not a removal

Status: done — 2026-10-27 (PR #275)

## Problem

A mission configuration (`ctld.configUser`) omits a list on purpose to remove it (ADR 0011).
But a configuration written before a catalogue version never had the lists that version added.
The Fat Cow (catalogue `2.3.0`) added `fatCowTypes`, `fatCowCrates`, `fatCowLoadouts` and `fatCowAICows`: in a `2.2.0` configuration CTLD read them as removed, and the Fat Cow was on with no aircraft, no crate and no loadout.

Found on 2026-10-27 vendoring rc14 into VMCT: the VEAF Open Trainings' `ctld-config.yaml` date from `2.2.0`, and the `.miz` published that morning carried a `CTLD_userConfig.lua` without a single Fat Cow list.
`ctld-tools` had the same gap: its completion (ADR 0011 Addendum 2) adds scalars and entry fields, never a whole list, and saving stamps the new version, which makes the omission a removal for good.

## Decision

ADR 0011 Addendum 3.
The build dates every list from the pinned shapes (`ctld-tools since` → `ctld.configListSince`); the engine and `ctld-tools` give a list its default when the configuration's `configVersion` is older than the list.

## Definition of done

- `ctld.configListSince` generated by the build and merged into `CTLD.lua`.
- `CTLDConfig:load()` gives a newer list its default, localised, and names it in the startup notice; an omission at or after the list's version stays a removal.
- `complete()` adds such a list when `ctld-tools` opens the configuration.
- busted and pytest cover both sides; docs (mission-maker configuration EN + FR), ADR, CHANGELOG.

## Not claimed

Not flown: the Open Trainings were completed by hand in their own `ctld-config.yaml` on 2026-10-27 and run with that, not with this fix.

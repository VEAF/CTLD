# 01 — Hand a DCS cargo-UI crate over to CTLD only once DCS has released it

## What to build

In the DCS-cargo-UI load hand-over of a type with `convertNativeLoadToCTLD`: after the release request and the existing delay, read the on-board
list and complete the hand-over only if the crate has left it (unreadable list = still on board). Otherwise keep the crate in DCS-native carry,
flag it as awaiting the hand-over and give the pilot the new message. Add the F10 *Fit parachute* action (enabled while a crate waits and the
aircraft is on the ground): it asks DCS for the release and completes the hand-over for the crates that left the list, or asks the pilot to open
the doors. Opening the doors alone does nothing. Add the message keys and the entry label and translate FR, ES, KO.

Tests first: in the native-cargo functional spec (an aircraft double that releases only with its doors open) and in a menu spec; the cases listed in
the PRD. Watch them fail, then implement.

Finish the lot: ADRs and glossary, documentation, CHANGELOG, backlog index and statuses, PR. Then the live check with the maintainer.

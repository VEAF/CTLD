# 01 — Hand a DCS cargo-UI crate over to CTLD only once DCS has released it

**Status:** ✅ done (PR #251) - live check by the maintainer pending · **Type:** HITL (live check by the maintainer in the UH-1H)

## Parent

[PRD — FIX-NATIVE-CONVERSION-DOORS](../PRD.md). Stories 1-13.

## What to build

In the DCS-cargo-UI load hand-over of a type with `convertNativeLoadToCTLD`: after the release request and the existing delay, read the
on-board list and complete the hand-over only if the crate has left it (unreadable list = still on board). Otherwise keep the crate in
DCS-native carry, flag it as awaiting hand-over and give the pilot the new message. While the carrier is on the ground, retry the release
each detection tick; a release of a flagged crate on the ground completes the hand-over through the existing CTLD load. At takeoff, stop
retrying and keep the crate native. Add the message key and translate FR, ES, KO.

Tests first, in the native-cargo functional spec: an aircraft double that releases only with its doors open (open by default); the cases
listed in the PRD. Watch them fail, then implement.

Finish the lot: pilot documentation, CHANGELOG, backlog index and statuses, PR. Then the live check with the maintainer.

## Acceptance criteria

- [ ] New cases fail before the change and pass after it (test committed first); existing native specs pass unchanged.
- [ ] A static object is never destroyed while the cargo is still on the on-board list.
- [ ] New i18n key regenerated by `merge_CTLD.ps1`, FR/ES/KO translated; CHANGELOG entry; docs; index `merged (PR #251)`.
- [ ] luacheck clean; `busted` green.
- [ ] Live check by the maintainer: doors closed at loading gives the message and a clean cargo window; opening the doors on the ground
      hands the crate over; the DCS cargo window shows no ghost.

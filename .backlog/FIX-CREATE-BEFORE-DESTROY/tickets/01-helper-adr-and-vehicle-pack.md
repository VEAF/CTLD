# 01 — All-or-nothing crate creation, ADR 0028, and the vehicle pack

**Status:** ⬜ ready · **Type:** AFK

## Parent

[PRD — FIX-CREATE-BEFORE-DESTROY](../PRD.md). Stories 1-3, 12-18, 20-21. GitHub issue #293.

## What to build

The foundation and its first user, end to end.

- **The shared helper.** One way to create a batch of crates all-or-nothing, with the arguments of the existing aligned crate creation: when
  every crate was created it returns them; when only some were, it removes those through the crate manager's own destroy (so `OnCrateCleared`
  fires for each, reason `destroyed`) and returns nothing; when none were, nothing.
- **The vehicle pack.** *Pack Vehicle* creates the crates first. Only once they all exist does it deregister the vehicle's JTAC, destroy the unit,
  and publish "ground unit removed". If the creation failed, the vehicle stays exactly where it was, still a registered JTAC if it was one; the
  pilot reads "Pack failed: the crates could not be created." (an existing key in the four dictionaries) and an ERROR line is logged naming the
  vehicle and the pilot's unit. No `OnVehiclePacked` is published on a failure.
- **`OnVehiclePacked`** publishes the number of crates actually created as `cratesSpawned`.
- **ADR 0028** (`dev/adr/0028-*.md`, plus its line in the ADR index): the rule "create the replacement first, destroy the original only once the
  creation succeeded", the all-or-nothing choice and why, the non-destructive reads that move before the creation, and the stepped-scene
  exception (PRD decision 3).
- **The backlog index** line of the lot in `.backlog/README.md` already exists ("in progress"); each delivering PR amends it, and the last one sets it to `merged (PR #NN)`.

## Acceptance criteria

- [ ] A refused creation (the crate creation double makes none of the crates) leaves the vehicle in place, tells the pilot "Pack failed: the crates could not be created.", logs an ERROR, publishes neither `OnVehiclePacked` nor "ground unit removed", and leaves a JTAC vehicle registered.
- [ ] A partial creation (some crates made) leaves no crate behind, the vehicle in place, and the same message and ERROR.
- [ ] The success path is unchanged for the pilot: same message "%1 packed into %2 crate(s).", same crate placement, same menu refresh.
- [ ] The existing test that freezes `cratesSpawned` to the requested count is rewritten to the created count; each new case fails before the change and passes after it.
- [ ] The helper has its own cases: all, some (rolled back, `OnCrateCleared` per removed crate), none.
- [ ] ADR 0028 written and indexed; no legacy-parity concern recorded on the success path.
- [ ] CHANGELOG `[Unreleased]` entry; `busted tests/ci/` green; luacheck clean; dictionaries unchanged (no new key) or regenerated by `merge_CTLD.ps1`.
